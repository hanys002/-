# 벤치마킹: 기술법인 진성 「진성 AI 사무실」

> 출처: 진성 측 시연 화면녹화(2026-11-06 작업분, 26분 작업을 2분 30초로 요약, 무음).
> 이 문서는 화면에 보인 내용만 정리했다. 보이지 않은 내부 구현은 `추정`으로 표시했다.

## 1. 한 줄 요약

**"지시는 말로, 실행은 AI가, 최종 승인은 사람이"**
대표가 오케스트레이터(김실장 = Claude)에게 말로 지시하면, 김실장이 부서(서브에이전트)에 배정하고,
결과를 취합해 보고하며, 외부로 나가는 행위(메일 발송 등)는 대표 승인 뒤에만 실행한다.

## 5. 배울 점 (설계 원칙으로 채택)

1. **단일 창구**: 대표는 실장 한 명에게만 말한다. 부서 배정은 실장이 한다.
2. **보고 형식 고정**: 결론 → 꼭 고칠 것 → 고치면 좋을 것 → 손대지 않는 것 → 파일 처리.
3. **검토와 수정 분리**: 검토 단계에서는 파일을 건드리지 않는다. 수정은 지시가 있을 때만.
4. **근거 대조**: 수치는 원자료(테스트 결과)와 대조하고, 부풀리지 않으며, 집계 기준을 장표에 밝힌다.
5. **되돌릴 수 있게**: 수정 전 버전 백업, 수정 후 해시 대조, 렌더링 이미지로 글자 넘침 검수.
6. **원천 재확인**: 제출처, 제목, 파일명 같은 외부 요건은 원래 공지(카톡 등)를 직접 열어 재확인한다.
7. **외부 행위는 승인 게이트**: 메일 발송, 제출, 게시는 반드시 대표 승인 뒤.
8. **판단은 사람에게 되묻기**: 사실관계를 AI가 확정할 수 없는 항목(실제로 그 시스템을 썼는지 등)은 질문한다.
9. **가시성**: 업무 보드와 사무실 시각화로 누가 무엇을 하는지 실시간으로 보인다.
10. **파일 충돌 방지**: 에이전트가 수정 중인 파일은 사람이 저장하지 않도록 경고한다.
