# 정보통신 법령개정 주간 모니터링

첨부된 `정보통신_법령개정_모니터링_Vol.2_2026.10.19.pdf`의 구성을 참고한 별도 파이프라인입니다.
기존 채용 메일과 함께 사용할 수 있으며 채용 수집 설정·조회 이력을 변경하지 않습니다.
보고 기관과 메일 발신자 표시명은 **한영기술사사무소**입니다. `config/laws.yaml`의 `organization`으로 관리하며 HTML·PDF·메일 일반 텍스트에 동일하게 반영합니다.

## 채용 메일과 함께 운영하는 방식

| 항목 | 기존 채용 메일 | 법령 모니터링 메일 |
|---|---|---|
| 실행 파일 | `src.main` | `src.law_monitor` |
| 예약 | 매일 09:00 KST | 매주 월요일 09:00 KST |
| GitHub 작업 | `daily-job-digest.yml` | `weekly-law-monitor.yml` |
| 결과 위치 | `out/digest.html` | `out/laws/` |
| 실행 그룹 | `job-digest` | `weekly-law-monitor` |
| 조회 이력 | `state/seen.json` 갱신 | 채용 이력 읽기·쓰기 없음 |
| Gmail 인증 | 기존 시크릿 | 같은 시크릿 재사용 |

각 작업은 별도 GitHub 러너에서 실행되며 한쪽의 실패가 다른 쪽을 중단하지 않습니다.
월요일에는 두 종류의 메일이 각각 발송됩니다. Gmail 발송 제한이나 GitHub 대기열은 공통 외부 조건이므로 도착 시각은 달라질 수 있습니다.
현재 사용자 확인과 GitHub의 최근 4회 성공 기록으로 채용 메일 운영을 확인했습니다. 두 기능을 분리하기 위해 별도 저장소를 만들 필요는 없습니다.
추후 발신 계정을 분리해야 한다면 법령 워크플로의 `GMAIL_USER`/`GMAIL_APP_PASSWORD`에 연결되는 시크릿 이름만 별도로 지정할 수 있습니다.

## 제공 기능

- **매주 월요일 오전 9시(KST)** 예약 실행. GitHub Actions 대기열에 따라 실제 실행·도착은 늦어질 수 있습니다.
- 수신자 **hanys002@gmail.com**. `config/laws.yaml`의 `recipient`로 지정하며 기존 채용 메일의 `MAIL_TO`는 사용하지 않습니다.
- PDF에 명시된 17개 법령과 두 핵심 법령의 시행령·시행규칙 4개, 총 **21개 법령**을 조회합니다.
- 지난 월요일부터 일요일까지의 공포·시행, 보고일 당일을 포함한 30일 및 6개월 내 시행 예정 항목을 표시합니다.
- 정보통신공사업법·전파법은 현행과 대상 개정 버전의 개정이유·개정문·부칙 및 이전 시행 버전과의 전체 조문 비교를 제공합니다.
- 한글 HTML 메일과 같은 내용의 **PDF 첨부**, 검증 가능한 JSON 결과를 생성합니다.
- 목록/본문 조회 실패, 정확한 명칭 미검색, 이전 버전 누락을 별도로 표시합니다. 전체 목록 조회 실패 시 메일을 보내지 않습니다.

첨부 PDF의 과거 개정 내용을 최신 사실로 복사하지 않습니다. 전체 84건 등록부와 행정규칙 17건의 목록은 첨부에 없어 포함하지 않았습니다.
국가정보보안기본지침·국회 의안·미공포 입법예고는 수동 확인 대상으로 표시합니다.
추가 대상은 `config/laws.yaml`의 `laws`에 국가법령정보센터의 정확한 명칭으로 넣습니다.

## GitHub Actions에서 활성화

1. 변경 파일을 저장소의 기본 브랜치 `main`에 반영합니다. 예약 실행은 기본 브랜치의 워크플로에만 적용됩니다.
2. [국가법령정보 공동활용](https://open.law.go.kr/)에서 법령 목록·본문 API 이용을 신청하고 승인된 **OC**를 확인합니다.
   저장소 **Settings → Secrets and variables → Actions → Variables**에 `LAW_API_OC`를 설정합니다.
   OC는 일반적으로 신청 이메일의 사용자 부분이지만 **수신자 주소로 추정하여 넣지 말고 승인된 값을 사용**하세요.
   같은 이름의 Repository secret을 쓰는 것도 지원합니다(Variable이 우선).
3. Repository secrets에 `GMAIL_USER`, `GMAIL_APP_PASSWORD`를 설정합니다. 기존 채용 메일용 시크릿이 있으면 그대로 재사용합니다.
   Google 2단계 인증 후 발급한 Gmail 앱 비밀번호를 사용하며 코드·YAML·채팅에 비밀번호를 넣지 않습니다.
4. **Actions → 정보통신 법령개정 주간 모니터링 → Run workflow**에서 처음에는 `dry_run`을 켭니다.
   실행 로그와 `law-monitor-…` 아티팩트의 조회 상태·공식 원문·PDF 한글 표시를 확인합니다.
5. `dry_run`을 끄고 실행하면 지정된 수신자에게 실제 발송합니다. 이후 매주 월요일 자동 발송됩니다.

SMTP 서버가 메일을 수락한 것과 최종 수신함 도착은 다릅니다. 처음에는 받은편지함/스팸함도 확인하세요.
수동 실행이나 재실행은 다시 발송합니다. SMTP 오류는 중복 전송을 피하기 위해 코드에서 자동 재시도하지 않습니다.

## 로컬 실행

Python 3.12, Pango/Harfbuzz 및 한글 글꼴이 필요합니다. Ubuntu에서 PDF 런타임 설치:

```bash
sudo apt-get update
sudo apt-get install -y libpango-1.0-0 libpangoft2-1.0-0 libharfbuzz-subset0 fonts-noto-cjk
```

저장소 루트에서:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-law.txt
python -m unittest discover -s tests -p 'test_law*.py' -v

# LAW_API_OC가 환경에 설정되어 있어야 함. 메일은 보내지 않음.
python -m src.law_monitor --dry-run

# GMAIL_USER / GMAIL_APP_PASSWORD도 설정된 환경에서 실제 발송
python -m src.law_monitor --send
```

기본 동작은 파일 생성만 합니다. 결과는 `out/laws/정보통신_법령개정_모니터링_YYYY-MM-DD.{html,pdf,json}`입니다.
`--date YYYY-MM-DD`, `--output DIR`, `--config FILE`로 기준일·출력 위치·대상을 조정할 수 있습니다.
`--date`는 확보된 버전을 기준일로 필터링하는 옵션이며, 당시 서버 상태를 복원하는 역사적 조회 기능은 아닙니다.
채용 수집에 필요한 Playwright/Chromium은 이 법령 보고서 생성에는 사용하지 않습니다.

인증정보 없이 한글 PDF 생성·형식을 점검하려면:

```bash
python -m src.law_monitor \
  --config tests/fixtures/law/config.yaml \
  --fixture tests/fixtures/law/example.json \
  --date 2026-10-19 --output out/laws-example
```

이 결과는 **가상 예시 데이터**로 표시되며 `--send`와 병용할 수 없습니다.

## 데이터 의미와 실패 판정

- 공식 DRF `lawSearch.do`/`lawService.do` XML API를 사용합니다. 연혁·시행예정·현행 목록을 끝까지 조회하며 페이지 반복·누락은 오류로 취급합니다.
- 법령명은 공백·가운뎃점 차이를 제외하고 정확히 일치해야 합니다. 명칭 변경으로 검색되지 않으면 대상 목록을 검토하세요.
- 통계 단위는 법령 버전이며, 같은 버전이 공포와 시행 조건을 모두 만족해도 한 번 집계합니다.
- API 목록의 **대표 시행일** 기준입니다. 부칙의 조문별 단계 시행일을 자동으로 해석하거나 별도 일정으로 추출하지 않습니다.
- ‘6개월’은 180일이 아닌 달력상의 6개월입니다. ‘기간 내’에는 보고일이 포함되지 않고 ‘시행 예정’에는 보고일 당일이 포함됩니다.
- 실무 영향이나 적용례를 AI로 추정하지 않습니다. 개정이유·개정문은 공식 원문을 제공하고, 기계 비교를 공식 신·구조문 대비표라고 표시하지 않습니다.
- 핵심 법령의 비교 기준은 대상 버전보다 먼저 시행되고 대상 공포일까지 공포된 가장 최근 버전입니다. 일부 시행일이 겹치는 복잡한 개정은 원문을 함께 확인하세요.
- 점검 기간 밖의 현행본은 설명을 위한 기준본으로 표시하며 이전 버전 비교 대상이 아닙니다. 기간 내 공포·시행 및 시행 예정 버전의 비교 자료가 없으면 계속 미완료로 표시합니다.
- 조문·원문을 30개 같은 임의 개수로 잘라내지 않습니다. 따라서 큰 개정은 PDF가 길어질 수 있습니다.
- 종료 코드 `0`: 확인 완료, `1`: 일부 목록/본문 확인 미완료(경고 보고서는 발송될 수 있음), `2`: 설정·출력·발송 오류 또는 전체 목록 조회 실패.
- 일부 조회 실패 시 메일 제목에 `[일부 조회 미완료]`가 붙고 Actions도 실패로 표시됩니다. ‘0건’만 보고 변경이 없다고 판단하지 마세요.
- 사용한 API 응답 본문은 JSON에 필요한 필드만 보관하고 OC·SMTP 비밀번호는 출력하지 않습니다.
